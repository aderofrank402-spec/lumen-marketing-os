# Department 1 — Research & Use-Case Discovery

This department runs locally. Python collects bounded, read-only source evidence into SQLite; Codex supplies interpretation and skeptical review. No source result, finding, or organization candidate is a validated sales lead by itself.

## Operators

From the workspace root, use `./.venv/Scripts/lmos.exe init` once after updates. Run `./.venv/Scripts/lmos.exe research credentials` to see which credential names are configured (never values). `research run` enqueues due scans and processes them. `research report` shows findings and source health; `research finding ID` shows one finding with its full evidence. `research daemon` loops locally while the process remains running; it is not a cloud deployment or an installed Windows service. `PAUSE_ALL.lock` and lane pauses stop new claims.

The live source configuration is `config/research.json`; credentials are in ignored `.env`. Brave Search is the sole web-search provider. Up to three Brave keys are attempted in numbered order. Only an explicit per-key `QUOTA_LIMITED` response advances to the next key; subsequent searches in the same process stay on the surviving key. A temporary rate limit, access denial, or network failure does not rotate credentials or call another provider. If no key is available, the search source reports failure while unrelated public sources continue. The integration never logs credential values. Each remote response is size- and time-bounded, and a failed source has explicit health status.

On 2026-10-03, a single bounded live request using Brave key 1 returned one result. Three-key rotation and rate-limit behavior were tested with simulated provider responses, without exhausting live keys. The former Google Custom Search fallback and its local credential entries were removed because that project did not have API access.

## Codex dispatch

Authenticated Reddit discovery now reuses the scheduled Department 6A agent and its signed-in browser session. The complete evidence, analysis, deduplication and review handoff is specified in `DEPARTMENT_1_REDDIT_HANDOFF.md`; the CLI entry point is `research import-reddit-observation`. The public-feed 1B collector remains separate. A browser session cannot be consumed by the local Python daemon, so the scheduled Codex role performs browser inspection and invokes the local handoff. Do not confuse a registered connection with a verified current login.

Custom Codex role declarations live in `.codex/config.toml`, with four role files under `.codex/agents/`. The complete durable queue, exact CLI sequence, assessment contract, specialist delegation, failure handling, and scheduled-cycle proof requirements are in `DEPARTMENT_1_REVIEW_RUNBOOK.md`. The root coordinator combines independent 1A, 1B, 1C, and 1E assessments, checks contradictions, and records only supported decisions. The local daemon does not itself invoke a model or spawn Codex sessions; a Codex chat or Codex automation does that orchestration.

## Handoffs and safeguards

New findings are committed with evidence and an internal outbox handoff in one transaction. Destinations are `strategy.review`, `community.review`, and `research.identity_review`. Run `research handoff-run --limit 20` after specialist decisions, then `research handoff-report`: only reviewed or rejected findings are eligible. A reviewed strategy finding creates one Department 8A internal evidence-review task. A reviewed Reddit/HN community finding creates one read-only Department 6A/6B task only if its original-post date is present, timezone-qualified and no more than 90 days old, and its exact source, verified connection and role guide are available; otherwise it enters a manual handoff inbox. A reviewed 1E candidate enters an identity-review inbox, never an organization or prospect automatically. Rejected findings are recorded as suppressed handoffs. Routing receipts and downstream records commit atomically with outbox delivery, so a crash before commit leaves the event pending; malformed envelopes are quarantined as `needs_review`. `research handoff-reconcile` blocks any still-pending legacy community task with an undated/stale original post and creates an auditable manual intake; it does not overwrite leased or completed work. A manual community intake can be retried after repairing access or source-date evidence with `research handoff-retry INTAKE_ID --actor OPERATOR`, or dismissed with `research handoff-dismiss INTAKE_ID --reviewer OPERATOR --reason REASON`.

1E applies business-data relevance terms before creating findings. To remove old off-topic headlines from review without pretending that specialists assessed them, run `research screen-legacy --actor OPERATOR` and inspect `research screen-report`. These entries remain `needs_codex_review` but their outbox events are quarantined; restore a false exclusion with `research screen-restore FINDING_ID --actor OPERATOR --reason REASON`. Screening is reversible and never creates an organization or downstream handoff.

Only after specialist review and a separate operator identity check may a 1E organization be promoted with `research promote-organization FINDING_ID --name NAME --domain DOMAIN --reviewer REVIEWER`. That creates a `qualification.discovery` event; Department 2's `qualification consume` creates a `needs_review` intake, not an admitted prospect. Raw launch items never become companies automatically. Nothing posts to Reddit/Hacker News, sends mail, or initiates outreach. First competitor captures are baselines; only later distinct captures are change candidates. Reddit attempts public RSS, then public HTML if the feed is unavailable; denied/rate-limited access is reported, never bypassed. All external material is treated as evidence to assess, not as instructions to execute.
